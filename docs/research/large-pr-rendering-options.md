# Rendering and lazy-loading audit for PRs with more than 1,000 files

Date: 2026-11-02. Scope: renderer and the exact installed `@pierre/diffs` **1.4.3**, not the latest upstream documentation. This is a primary-source audit, not a measured speedup claim. Production code was not changed. Core fingerprint/read timings are a separate investigation.

The companion [measured investigation](large-pr-performance.md) now includes a synthetic reproduction of the loading-placeholder cascade and core timing results. Hypotheses below retain the source-audit distinction; use the companion report for measured claims.

## What is already lazy

- File-content reads are deferred until a card is within **1,500 px** of its scrollport, unless it is the selected thread/declaration or its contents are already cached. Both old/new query fetches are gated by `near`. A `wasNear` latch means this is **load-once-near**, not an eviction/windowing policy. [Viewer:204–245](/Users/florianwagner/Developer/coxswain/src/renderer/src/Viewer.tsx:204)
- Pierre’s simple `Virtualizer` already limits rendered code rows and replaces offscreen diff bodies with height placeholders. It does **not** unmount coxswain’s enclosing React `Viewer` and its hooks. Its default overscroll is 1,000 px and IntersectionObserver margin is 4,000 px; these library margins are distinct from coxswain’s 1,500 px file-read margin. The React wrapper accepts a `config` prop. [VirtualizedFileDiff:696](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/components/VirtualizedFileDiff.js:696), [Virtualizer defaults](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/components/Virtualizer.js:5), [React config](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/react/Virtualizer.d.ts:5)
- Syntax highlighting already uses a shared worker pool and token transformer. Adding a worker pool is not a new optimization. The installed worker manager defaults to eight workers and separate 100-entry file/diff AST LRUs; coxswain currently supplies only `workerFactory`, so those library defaults apply. [App provider](/Users/florianwagner/Developer/coxswain/src/renderer/src/main.tsx:43), [pool/cache defaults](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/worker/WorkerPoolManager.js:58), [worker creation](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/worker/WorkerPoolManager.js:302)
- The full Files sidebar uses Pierre’s `FileTree`; its model/input preparation is already separate from the variable-height review sidebar projection. [Files tree](/Users/florianwagner/Developer/coxswain/src/renderer/src/Navigator.tsx:509)

## Work still proportional to the whole PR

### React shells, observers and listeners

`App` maps every shown code part to a mounted `Viewer`; only its returned body becomes a cold placeholder. A cold mounted Viewer still creates three query observers (theme, old contents, new contents), an appearance `MutationObserver` and media listener, a Find registration, and three window-level keyboard/blur listeners. Unseen, uncollapsed cards also each have an IntersectionObserver. Query observers do not mean three network/IPC reads: their caches and `enabled` gates still apply. [all-card map](/Users/florianwagner/Developer/coxswain/src/renderer/src/App.tsx:1878), [theme/read queries](/Users/florianwagner/Developer/coxswain/src/renderer/src/Viewer.tsx:201), [appearance subscription](/Users/florianwagner/Developer/coxswain/src/renderer/src/components/useCodeThemeType.ts:4), [window listeners](/Users/florianwagner/Developer/coxswain/src/renderer/src/Viewer.tsx:298), [Find registration](/Users/florianwagner/Developer/coxswain/src/renderer/src/code-find.ts:159)

A sweep through a large PR leaves its loaded `Viewer` shells and source/query observations mounted. Guide, Changes and Files also retain separate canvas surfaces while switching between them. Inactive surfaces are `visibility:hidden`/`inert`, not unmounted. This deliberately preserves measured heights and reading state, but means the current boundary is a workspace, not a bounded number of file cards. Hidden geometric IntersectionObservers are not explicitly suspended by this code; whether they add background reads should be profiled. [latch](/Users/florianwagner/Developer/coxswain/src/renderer/src/Viewer.tsx:209), [retained surfaces](/Users/florianwagner/Developer/coxswain/src/renderer/src/components/RetainedCanvas.tsx:20), [visibility implementation](/Users/florianwagner/Developer/coxswain/src/renderer/src/components/RetainedCanvas.tsx:60)

### A possible lazy-load cascade

Cold placeholders reserve an estimated height, up to `44 + 20 * 200` px. Once `near` becomes true but reads are still pending, the component instead returns an unsized `Loading…` container; `Centered` only has flex/padding styles. The estimate therefore is not carried through the loading phase. **Hypothesis to measure:** shrinking placeholders brings subsequent cards into the read margin, which starts more reads, changes more heights and causes a burst of work and scroll corrections. Stable pending heights and a bounded visible-first read queue are a small, high-value experiment. This audit establishes the code path, not that the cascade occurred in a recorded real PR. [placeholder branches](/Users/florianwagner/Developer/coxswain/src/renderer/src/Viewer.tsx:495), [Centered sizing](/Users/florianwagner/Developer/coxswain/src/renderer/src/components/layout.tsx:228)

### Diff calculation is not all off-thread

`MultiFileDiff` receives old/new text, not precomputed metadata. In 1.4.3, `useEffectiveFileDiff` invokes `parseDiffFromFile` synchronously inside React `useMemo`; worker use is separate. A large newly visible file can therefore block the renderer before worker highlighting finishes. The separate public React `FileDiff` component accepts precomputed `fileDiff` metadata (`MultiFileDiff` itself accepts old/new file pairs only), so parsing can be moved to a worker/core seam while retaining Pierre and the existing per-card structure. Cache it by immutable old/new blob identity and parsing options. Find currently has another on-demand `parseDiffFromFile` path and should reuse that metadata where practical. [current inputs](/Users/florianwagner/Developer/coxswain/src/renderer/src/Viewer.tsx:722), [synchronous parsing](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/react/utils/useFileDiffInstance.js:132), [metadata input](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/react/FileDiff.d.ts:6), [Find parse](/Users/florianwagner/Developer/coxswain/src/renderer/src/code-find.ts:73)

### Sidebar and entry-index work

- Changes explicitly asks Pierre’s model for **all expanded rows**, then renders that projection; expanded does not mean within the scroll viewport. The code already records this windowing debt. Its `reviewed.includes(path)` checks are repeated over files and can become `O(F*R)`; use a `Set` before measuring a larger renderer rewrite. [projection](/Users/florianwagner/Developer/coxswain/src/renderer/src/ChangesNavigator.tsx:177), [debt](/Users/florianwagner/Developer/coxswain/src/renderer/src/ChangesNavigator.tsx:153), [membership checks](/Users/florianwagner/Developer/coxswain/src/renderer/src/ChangesNavigator.tsx:39)
- Guide’s `threads(index)` reconstructs a Map of **all changed files once per section**: `O(S*F)` map work for S sections and F changed files. It also does `sectionFiles.find(...)` for each row (potential `O(F_i²)` within a section), while assigning entries to sections searches sections/files. These are code-derived complexities, not measured bottleneck rankings. Hoist/index once per immutable input. [entry grouping](/Users/florianwagner/Developer/coxswain/src/renderer/src/Sections.tsx:109), [per-section map and lookup](/Users/florianwagner/Developer/coxswain/src/renderer/src/Sections.tsx:125)
- Each rendered Viewer runs `entries.find(...)` and `entries.filter(...)` over the shared workspace entries. On an update that invalidates many Viewer props, this is `O(F*E)` rather than indexing entries once by path/thread. In particular all Viewers receive the shared turns object, so thread streaming is worth measuring alongside static mounting. Stable memoized per-path projections would reduce unrelated work. [root lookup](/Users/florianwagner/Developer/coxswain/src/renderer/src/Viewer.tsx:203), [root filter](/Users/florianwagner/Developer/coxswain/src/renderer/src/Viewer.tsx:454), [shared props](/Users/florianwagner/Developer/coxswain/src/renderer/src/App.tsx:1314)

## Capabilities already in pinned Pierre 1.4.3

`CodeView` is already shipped in this installation. It virtualizes **file items**, releases off-window item DOM, reuses a bounded element pool, and creates React annotation/header portals only for rendered item snapshots. Its scroll API accepts item IDs and line/side targets; item versions and update APIs let a caller retain identities. [item release/pool](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/components/CodeView.js:505), [window loop](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/components/CodeView.js:1629), [React portals](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/react/CodeView.js:321), [public handle](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/react/CodeView.d.ts:75), [line target](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/types.d.ts:447)

Important limits:

- `CodeViewDiffItem` requires `FileDiffMetadata`. It does **not** take a path and asynchronously calculate its diff for free. A caller must obtain metadata (possibly from a patch/worker) before constructing an item. Whole-file items require `FileContents`. [item types](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/types.d.ts:413)
- `loadDiffFiles` is available for **hydrating partial diff metadata** with full old/new contents; it is not an async `parseDiffFromFile` replacement and is not an AbortSignal-aware fetch queue. [loader type](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/types.d.ts:47), [hydration checks](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/components/FileDiff.js:509)
- It supplies file/diff items and headers/footers, not arbitrary Guide prose/diagram/section-layout items. A Changes-only prototype is much smaller than migrating Guide’s side-by-side section explanations, sticky headers and prose threads. [item union](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/types.d.ts:441), [React render hooks](/Users/florianwagner/Developer/coxswain/node_modules/@pierre/diffs/dist/react/CodeView.d.ts:59)
- Windowing DOM is not equivalent to an unlimited text/metadata memory reduction: lightweight item/instance records and input metadata still exist. Off-window React thread unmounts also require drafts/expanded state to move outside transient annotation components.

No recommendation here requires an unverified newer Pierre version.

## Recommended experiments, in order

1. **Stabilize loading placeholders and schedule visible reads.** Preserve an estimate/measured height through pending/error/plain/diff states. Prioritize actual viewport and explicit click targets over lookahead, bound concurrent loads, and stop enqueueing obsolete destinations. Measure cold first-paint latency, peak simultaneous reads and height correction count before/after.
2. **Remove repeated whole-PR work.** Precompute `Set`s and path/thread/section Maps; share appearance and modifier-key subscriptions rather than creating thousands; keep only lightweight Find metadata registered offscreen. Measure React mount/update time and a streamed reply on 100/1,000/2,000-file synthetic fixtures.
3. **Prototype a Changes-only file-item window.** Compare existing simple Virtualizer with CodeView (same pinned dependency) or a measured-height outer window. Maintain stable file IDs, per-file metadata caches, bounded overscan and explicit target mounting. Keep Guide as-is in this prototype. Measure mounted Viewers/listeners/DOM/heap before and after a complete scroll sweep, not only first load.
4. **Move/cache diff parsing separately.** Feed precomputed metadata to avoid synchronous React parsing for large files; reuse metadata for Find. Measure files by byte count/hunk complexity, not only total PR file count. Highlight workers are already present.
5. **Window review sidebar rows.** Use variable-height file/thread groups and stable row IDs; preserve keyboard traversal, section/file reveal, focus and review controls for offscreen rows. Native Files tree is already a different, virtualized path.

Do not increase the worker count or prefetch margin on assumption alone: more concurrency can improve idle throughput while worsening interactive latency and memory. Test pool sizes/read concurrency/overscan independently.

## Acceptance checks for any implementation

Use a reproducible 1,000–2,000-file synthetic PR with many small files plus a few large text/generated/binary files. Record cold first usable viewport, click-to-first-target-code p50/p95, main-thread tasks over 50 ms, mounted card/query/observer counts, source/AST memory and peak read/highlight queue depth. Compare cold and warm navigation and a complete scroll sweep.

Preserve Back/Forward/workspace/pane positions, hidden/reviewed exceptions, same-file thread-to-header clicks, links to declarations in collapsed context, thread drafts and permissions, sidebar keyboard/Space review, search including offscreen files, and stable reading anchors while lazy items change size. Keep one scroll owner; replacing mount behavior must not reintroduce the recently fixed correction loops.
