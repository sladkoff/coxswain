# coxswain — ubiquitous language

The terms used in code, docs and conversation. One file per bounded context.
If a term's meaning changes, update it here first.

Draft: these are working definitions for finding out how the concepts relate. Open questions are
listed at the end.

## Terms

**Find**: literal text search in the last-used pane, opened with ⌘F. On the canvas it searches the files and
file diffs currently shown, across the selected range or view, including off-screen files. A whole-file canvas
searches that file. In the agent pane it searches the selected session's chat. Next and Previous move between
matches without adding steps to History. This is separate from Open Quickly (file names) and Find Usages (code names
throughout the worktree).

**Attachment**: an image or file added to the agent pane's composer by picking, dropping or pasting it.
It travels with the message, with a removable preview before sending and a preview in the chat afterwards.
Images and small text files are sent as content; other files are references to their original local paths.
This is separate from a **view prompt**, which can accompany the same message.

| Term                     | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Not to be confused with                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **Project**              | A git repository the user has added to coxswain, together with its worktrees, entries and agent sessions. The top-level thing you open. Added three ways ([ADR 0040](../adr/0040-local-repositories-and-optional-github.md)): a GitHub repository, which coxswain clones; _Add Local Repository…_, a repository already on the machine, used in place; or _New Project…_, a new folder coxswain makes and `git init`s. A project may be **on GitHub** (`owner/name`), and only then has PRs, review threads and posting.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | _Repository_: the project is coxswain's view of a repository.                                                                               |
| **Repository**           | A git repository. Either coxswain's clone of a GitHub repository, or the user's own on this machine (a **local repository**), which may have a remote on GitHub (`owner/name`), on another host, or none; only GitHub repositories have pull requests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | _Worktree_: the repository is shared; a worktree is one checkout of it.                                                                     |
| **File**                 | A path in a repository, read at one revision or from a worktree.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | _File diff_: a file is contents; a file diff is a change.                                                                                   |
| **Pull request (PR)**    | A GitHub request to merge a head branch into a base branch of a repository. Has an author, reviewers, file diffs, review comments and a conversation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | _Branch_: a PR points at a branch but also carries review state and conversation.                                                           |
| **File diff**            | The change to one file between two revisions: in a PR (base → head), or in a worktree (its base → working state).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | _Diff_: the whole set of file diffs of a PR or worktree.                                                                                    |
| **Commit diff**          | The file diffs of one commit: its first parent → the commit. The canvas shows one in place of all changes when a commit is picked under _Commits_.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | _Diff_: all changes, merge base → worktree.                                                                                                 |
| **Comment**              | A GitHub comment on a PR: a review comment or a comment in the conversation. Written for a collaborator to read and answer. A review comment is mirrored into its workspace as an entry of kind _comment_ (the user's own as notes, theirs to edit and delete), overwritten by every read, and deleted here when its thread is gone from GitHub ([ADR 0037](../adr/0037-pull-request-sync-and-posting.md)). _Post_ makes new ones from the user's notes; a posted note keeps its GitHub comment, so editing or deleting it here does so there too, and replies there show in its thread.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | _Note_: yours, written in coxswain; a comment once posted.                                                                                  |
| **Entry**                | One comment of a workspace's review, in coxswain: a note, a question, an answer, an explanation, a finding, or a review comment mirrored from GitHub (by its author). Belongs to its workspace ([ADR 0015](../adr/0015-entries-pinned-and-outdated.md)). Has an anchor, or is a reply in a thread. Records the range it was written in (a view's or commit diff's, or the worktree) and its revision: the commit its lines are at, a snapshot of the worktree on the live diff. An explanation or finding belongs to its view too, and shows only while that view does. Shows between the lines in any range where its lines are, unchanged. The UI never shows the word _entry_.                                                                                                                                                                                                                                                                                                                                                                                                     | _Chat entry_: a line of an agent session's transcript in the agent pane.                                                                    |
| **Note**                 | An entry written by the user. In a comment thread, a comment of theirs: private until posted, then posted as written. In an agent thread, something for the agent, sent with the next question.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | _Comment_.                                                                                                                                  |
| **Question**             | A comment sent to the agent: an entry sent as a turn to the workspace's current agent session, the agent pane's ([ADR 0021](../adr/0021-comments-go-to-the-agent-pane.md)). Only in an agent thread. The agent pane shows it as a card with _View thread_; the agent's reply is kept as an answer in the thread. The agent may act on it. A note in an agent thread becomes one when the thread is sent to the agent. A follow-up question goes to the current session too; if the thread's last question went to another, the whole thread goes with it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | _Note_: a comment that stays with you.                                                                                                      |
| **Answer**               | An entry holding the agent's reply to a question.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |                                                                                                                                             |
| **Explanation**          | An entry the agent writes on lines while making a view, saying what they do and why, to help the user read them. Labelled _Explanation_. Starts a thread like a note.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | _Finding_: an explanation only helps; it doesn't judge.                                                                                     |
| **Finding**              | An entry the agent writes on lines when asked to review: a bug, a risk, a question or a suggestion of its own. Opt-in: only when the user asks for a review.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | _Review comment_: GitHub's. _Explanation_.                                                                                                  |
| **Thread**               | Every anchored note, question, explanation or finding starts a thread: its replies and the agent's answers, in order, shown between the lines at its anchor. A thread is a _comment thread_ or an _agent thread_, by its first entry, and stays one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |                                                                                                                                             |
| **Comment thread**       | A thread started by the user's note (_Comment_ in the composer) or by a comment from GitHub: what the user says to the PR's author. Its replies are comments too; it never goes to the agent as a conversation. _Submit Review_ takes the open ones: _Post to GitHub_ posts their comments as written, _Send to Agent_ hands them to the agent to implement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | _Agent thread_.                                                                                                                             |
| **Agent thread**         | A thread started by a question (_Agent_ in the composer) or by the agent's explanation or finding: for exploring the code or changing it with the agent. Stays out of _Submit Review_. _Summarize as Comment_ turns where it got to into a new comment thread on the same anchor.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | _Comment thread_.                                                                                                                           |
| **Anchor**               | Where an entry points: a line range in a file or on one side of a file diff, with the code as it was then. Line numbers drift as the worktree changes; the code doesn't. Or a passage of a view section's prose, with its text (its _quote_), pinned to the section as it was ([ADR 0036](../adr/0036-threads-on-view-prose.md)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |                                                                                                                                             |
| **Post**                 | Putting comment threads on the PR on GitHub, so a collaborator can see them: _Submit Review › Post to GitHub…_ sends the picked threads' comments, as written, in one review with a verdict and a summary ([ADR 0037](../adr/0037-pull-request-sync-and-posting.md)). A new thread on lines the PR's diff has becomes a thread there (its first comment on the lines, the others replies) and stays linked to it; on a thread already on GitHub each comment is a reply; any other new thread goes as linked comments in the PR's conversation, led by a permalink GitHub shows as the code where it has the lines (else the code quoted). A review of the user's in progress on GitHub is only added to once they agree. Always an explicit action: _Post to GitHub_ in the comment box (one global preference) posts each comment as it's sent, as plain discussion with no review (on its lines, or in the PR's conversation); otherwise comments wait for _Submit Review_.                                                                                                        |                                                                                                                                             |
| **Summarize as Comment** | An agent thread's ⋯ menu item: the summary model writes the one review comment the thread comes to, the reviewer's point in their voice, for a PR author who never saw the thread, with the agent's answers as background (or that nothing is left for the author); the user edits it below the thread, and saving adds it as a comment thread on the same anchor. A job, shown in Activity.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | _File summary_: what changed in a file diff, also the summary model's.                                                                      |
| **Resolved**             | A thread the user has marked done. It folds to one line between the lines, is left out of _Submit Review_, and can be reopened. Stored on the thread's first entry. On a thread from GitHub, a resolve there is taken over, and one here goes there at once while _Post to GitHub_ is on, else with the next _Submit Review_.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | _Outdated_: a fact about the code; resolved is the user's decision.                                                                         |
| **Outdated**             | An anchored entry whose lines have changed since it was written, e.g. by an agent's edit: followed from its revision to the live diff (the worktree; the merge base for removed lines), moving with lines added or removed around them. The same whatever range is on screen. Not shown between the lines, except in a range that still has its lines, such as its own commit diff; its file diff's header says _N outdated_ and shows it with its code then and now. It stays open until resolved. An entry with no revision is outdated. Its opposite is **current**. An entry on a view's prose goes outdated when its section is rewritten, and shows at the top of the section.                                                                                                                                                                                                                                                                                                                                                                                                  | _Reviewed_: a decision about a file diff; outdated is a fact about the code.                                                                |
| **Review comment**       | A GitHub comment attached to a line or range of a file diff in a PR. One kind of comment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | _Note_.                                                                                                                                     |
| **Conversation**         | The PR's discussion thread (GitHub's "Conversation" tab): comments on the PR as a whole, not tied to a line.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | _Review comment_; GitHub Discussions, which coxswain doesn't use.                                                                           |
| **PR panel**             | The canvas's view of the workspace's PR on GitHub, opened by its chip (_#12_) in the canvas bar ([ADR 0037](../adr/0037-pull-request-sync-and-posting.md)): state, _Merge…_ or _Ready for Review_, checks, description, people and the conversation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |                                                                                                                                             |
| **Check**                | A CI result on a commit on GitHub: a check run (GitHub Actions, other apps) or a commit status. Passing, failing, running or neutral; a dot on the PR chip (the head's) and in the Commits pane (each commit's). A failing one can be sent to the agent with the end of its log.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |                                                                                                                                             |
| **Ask**                  | A message to the agent session in the agent pane, with what you want done, usually a change producing file diffs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | _Question_: a comment sent to the agent from a thread. _Prompt_: the text an ask turns into.                                                |
| **Workspace**            | A unit of work in a project, as shown in the sidebar: a PR being reviewed, or a branch started in coxswain to build something, which becomes the PR's workspace once a PR is opened for its branch ([ADR 0028](../adr/0028-branch-workspaces-and-snapshots.md)). Has one worktree, and its diff, entries, agent sessions and turns. Its branch has at most one PR, so a workspace has at most one; several PRs mean several branches, so several workspaces.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | _Agent session_: one run of an agent; a workspace can have many. _Project_: a project has many workspaces.                                  |
| **Branch workspace**     | A workspace started on a branch rather than a PR: a new branch made from a base branch (the default one unless another is picked), or a branch already on GitHub. Its diff is against where it forked from the base branch. _Open Pull Request…_ pushes it and opens a draft PR into the base branch; from then on it is that PR's workspace, in the same worktree.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | _PR worktree_: a branch workspace's worktree is on its own branch until it has a PR.                                                        |
| **Agent pane**           | The chat with the workspace's agent session, on the left of the main screen whenever a PR is open ([UX](../UX.md) L4).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | _Canvas_: the agent pane is where you talk to the agent; the canvas is what you both look at.                                               |
| **Canvas**               | The right side of the main screen ([UX](../UX.md) L3): one explorer that shows the workspace's contents and that both the agent and the human can annotate. It shows all file diffs one after another, a commit diff, or a view; or a whole file opened from _Files_.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | _Agent pane_.                                                                                                                               |
| **Navigator**            | The file list on the left of the canvas ([UX](../UX.md) L2), under its own bar, shown and hidden with ⌘B. The bar switches between _Changes_, the workspace's changed files, _Files_, the whole file tree of the workspace, _Commits_, the commits pane in its place, and _Turns_, the agent turns that changed the worktree.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | _Canvas_: the navigator lists files; the canvas shows them.                                                                                 |
| **Action**               | Something the user can do in the UI, by id: open a file, Back, show or hide Files, switch project, and so on. Every action is in one registry (ADR 0027); the command palette lists them, and native menu items and buttons run them by id. An action can be unavailable for now (e.g. Back at the start of the history), and is then left out.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | _Command palette_: where actions are found by name.                                                                                         |
| **Command palette**      | The search box ⌘K opens over the main screen. Typed text finds a file (Open Quickly); text after `>` finds an action to run. Both fuzzy, best match first.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | _Open Quickly_: the palette without the `>`, for files.                                                                                     |
| **Open Quickly**         | The command palette in its file mode, opened with ⌘⇧O: find any file of the workspace by path (fuzzy) and show it in the canvas, with the Navigator on _Files_.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | _Navigator_: browses the tree; Open Quickly jumps by name.                                                                                  |
| **Go to Definition**     | ⌘-click on a name or import path in the canvas: shows the file and line where it's defined, as the file's language server resolves it (by scope and type, not by name), at the revision the name was clicked in; picked from a menu if several. Also in a name's right-click menu. Only in files with a language server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | _Open Quickly_: finds a file by path; Go to Definition by a name in the code.                                                               |
| **History**              | What the canvas showed, in order, each step with where it was scrolled: each whole file, each file picked in _Changes_, each _Changes_/_Files_ switch, each commit or view picked and each workspace opened. _View > Back_ (⌥⌘←) and _Forward_ (⌥⌘→), or the canvas bar's chevrons, step through it; Back into another workspace's step opens that workspace. Gone on restart.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | _Commits_: the PR's git history, not the canvas's.                                                                                          |
| **Find Usages**          | In a name's right-click menu in the canvas: every place the file's language server finds that name referenced, its definition included, at the revision it was clicked in; picked from a menu to show it in the canvas. Only in files with a language server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | _Go to Definition_: where the name is defined; Find Usages: everywhere it is used.                                                          |
| **Guide**                | A view that goes through all of a workspace's diff in reading order, made by the agent pane's session with coxswain's tools ([ADR 0023](../adr/0023-guides-made-by-the-agent-pane.md)): its sections embed every file diff, with a sentence or two on what to look at, and explanations on lines. The file diffs no section embeds show after it, under _Not in the guide_. Asked for in the agent pane, or with _New View_ in the canvas's bar; with review, it has findings too.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | _PR description_: written by its author. _Review_: findings are the review part, and opt-in.                                                |
| **View**                 | An explanation of code or changes on the canvas, picked with the chips in its bar: _Diff_ (the file diffs, no view) or one the agent made with coxswain's tools ([ADR 0026](../adr/0026-views-in-markdown-with-mermaid.md)): a title and view sections of markdown, with diagrams, embedded file diffs and whole source files the user reviews and comments on. A view can explain existing code even when the workspace has no changes. A guide is one kind; others show one aspect, such as the data model or a data flow. Pinned to the merge base → a snapshot of the worktree then, local changes included, and shown over that range, not the live diff. **Stale** once the worktree moves on (new commits, the agent's or the user's edits), if it was pinned to the worktree; a view of a commit, an agent turn or what's on GitHub never is. Every view is kept until the user removes it (right-click its chip → _Remove View…_), with a chip named by its title (a repeated title gets a number: _Guide_, _Guide 2_); the newest shows. _New View_ asks the agent for one. | _Changes_: the Navigator's list of file diffs. _Display options_: the canvas bar's sliders menu.                                            |
| **Being written**        | A view while the agent turn that last changed it still runs: more may come, so the canvas says so above it and its chip turns a spinner. Not a step the agent takes: it ends with the turn, done, stopped or failed, and starts again when a later turn changes the view. Only in memory, like the turn.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | _Stale_: about the code moving on, not the view. _Draft_: nothing needs approving.                                                          |
| **View section**         | One part of a view: a heading (its entry in the view's table of contents), then markdown: prose, tables, mermaid diagrams, and the source files or file diffs it embeds. A path is embedded in at most one section of a view.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | _Thread_, _folder_: a section is by theme, not by place in the tree.                                                                        |
| **View prompt**          | What a view is asked for with: a title and a prompt, built in (_Guide_, _Review_, _Questions for the author_, _Data model_, _Data flow_) or the user's own, kept in Settings ([ADR 0031](../adr/0031-view-prompts.md)). Picked from _New View_, it is attached to the agent pane's composer as a card and sent with what the user types, which says what to focus on.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | _Ask_: the message it is sent in.                                                                                                           |
| **File summary**         | A sentence or two on what changed in one file diff, written ahead by the summary agent (a small model picked in Settings) so the agent pane's agent can plan a view without reading every diff first ([ADR 0029](../adr/0029-file-summaries-and-activity.md)). Kept under the file diff's fingerprint: never updated, a changed file diff gets a new one. A hint to plan with, not a fact about the code.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | A view section's prose, which the agent writes after reading the diff                                                                       |
| **Skill**                | A written method the agent pane's agent follows for one part of making a view, read with coxswain's `read_skill` tool ([ADR 0039](../adr/0039-skills-for-views.md)): `pr` for a view's overview, `writing-beats` for the order of its sections, `code-review` for findings in a review. Copied whole from an outside collection, each served with a note on how it applies in coxswain.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | A view prompt, which says what view to make; a skill says how to make part of it. The agent's own skills, which coxswain doesn't ship.      |
| **Job**                  | A piece of work coxswain does in the background, on the summary model, for one workspace ([ADR 0038](../adr/0038-background-jobs-and-core-events.md)): the file diffs of a range that had no file summary, or an agent thread to summarize as a comment. Started _ahead_ (something changed: a workspace opened, its HEAD moved), _for a view_ (a view was started) or _as a comment_ (Summarize as Comment). Running, done, failed or stopped; shown in Activity.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | A turn, which is the agent pane's. _Background task_: a command an agent left running.                                                      |
| **Activity**             | What coxswain does in the background, its jobs: a button at the canvas bar's right that turns while one runs and gets a red dot when one failed, and the list it opens.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | The agent pane's transcript                                                                                                                 |
| **Muted**                | A file diff or source file in a view that the reader can pass over: made by a tool (lockfiles, generated clients, snapshots), tests, a mechanical change, or what the user said doesn't matter to them. The agent marks its fence `muted` (`generated`, the word it had first, means the same). It's low-lighted, and so is a section of only those; the section's heading says why. A guide puts them in sections of their own at the end rather than leaving them out.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Not in the guide, which is only for files a guide missed                                                                                    |
| **Reviewed**             | A file or file diff the user has marked as reviewed, on the canvas. Belongs to the file diff's contents ([ADR 0014](../adr/0014-reviewed-follows-file-diff-contents.md)): stays reviewed while they're unchanged. In the live diff an agent's edit or new PR commits on that file make it unreviewed again; in a view, which is pinned, it stays, and a new view keeps it for file diffs that didn't change. Whole files embedded in views have separate Reviewed marks keyed by their contents, independent of a diff or its base; reviewing a file does not review its diff. Local to coxswain for now, not synced with GitHub's own _Viewed_ checkbox.                                                                                                                                                                                                                                                                                                                                                                                                                             | _Viewed_: its old name. _Outdated_: that is for entries, not files. A GitHub PR review ("alice reviewed") is about the PR, not a file diff. |
| **Worktree**             | One checkout of a repository at a branch, where code can be changed. Every agent session works in exactly one worktree.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | _Branch_: several worktrees can't share a branch; a branch exists without a worktree.                                                       |
| **PR worktree**          | A worktree checked out on a PR's head branch. Changes made there become new commits on the PR once pushed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |                                                                                                                                             |
| **Local change**         | A change in a worktree that isn't on GitHub: uncommitted or untracked files, or commits not pushed yet, i.e. what the worktree has on top of the PR's head (or the branch's on GitHub; its merge base while it isn't pushed). An agent session's changes are local changes until they're pushed. The Navigator marks files with them (●), and the commits not pushed say _not pushed_. The scopes _Not Pushed_ and _Uncommitted_ split them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | _File diff_ of the PR: what's on GitHub. _Scope_ shows either on its own.                                                                   |
| **Scope**                | Which part of the diff the canvas shows, carried and picked by the _Diff_ tab in its bar: _All_ (merge base → worktree), or one of the three layers that add up to it: _PR_ (what's on GitHub: merge base → its head; _On GitHub_ for a branch workspace without a PR), _Not Pushed_ (the commits not pushed yet: GitHub's head → HEAD) or _Uncommitted_ (what isn't committed: HEAD → worktree, untracked files included; _Uncommitted changes_ in the Commits pane).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | _View_: a view shows its own pinned range, not a scope.                                                                                     |
| **Snapshot**             | The worktree as a commit, uncommitted and untracked files included ([ADR 0028](../adr/0028-branch-workspaces-and-snapshots.md)): the worktree's HEAD when nothing is uncommitted. Views and turns are pinned to snapshots. The same files on the same HEAD make the same snapshot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | _Commit_: a snapshot is never on a branch or pushed.                                                                                        |
| **Clone**                | coxswain's own copy of a GitHub repository picked from its list, in `~/coxswain/repos/<owner>/<name>/` ([ADR 0008](../adr/0008-clones-and-pr-worktrees.md)). The project's worktrees are made from it. A local repository has none: its worktrees are made from the repository itself (ADR 0040).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | A local repository: the user's own, which coxswain adds worktrees to but never changes otherwise.                                           |
| **Language server**      | A program that understands one language's code and answers Go to Definition and Find Usages over LSP ([ADR 0034](../adr/0034-language-servers.md)). coxswain ships or fetches the ones it supports (TypeScript's `tsc`, pyrefly for Python) and runs one per checkout and language while they're used.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Not the agent: an agent may run its own language servers, coxswain never talks to them.                                                     |
| **Checkout**             | A revision's files on disk for a language server to read: the worktree itself, or for a commit (the other side of a file diff, a snapshot, a turn) a read-only copy made from the project's repository in `~/coxswain/checkouts/<owner>/<name>/<sha>/` (`local/<name>-<hash>/` for a local repository), with the worktree's dependencies linked in.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | _Worktree_: where code is changed; a checkout of a commit is only read.                                                                     |
| **User**                 | A GitHub account. Authors PRs and comments, reviews PRs. The _current user_ is whoever is signed in to coxswain.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | _Agent_: agent changes are made by a user's agent, but commits and comments show a user.                                                    |
| **Agent session**        | One run of a local coding agent (Claude Code or Codex) in one worktree: the ask that started it, its transcript and its resulting changes or answer. Its agent is picked when it starts and stays. Its live entries, running status and pending permission belong to the core and survive switching workspaces. Its **title** is the one its agent gives it (Claude Code names it after the first turn), else its first message's first line. A workspace's **current** session is the one last used (made, picked in the agent pane or sent a message): the pane opens it, and questions go to it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | _Agent_: the tool (Claude Code, Codex); an agent session is one use of it.                                                                  |
| **Agent status**         | What a workspace's agent is up to: _waiting_ (a permission to approve), _working_ (a turn runs), _done_ (a turn ended that the user hasn't looked at since) or _idle_. A workspace shows the first of its sessions' in that order, as a dot in the sidebar.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | _Running status_: a session's turn running or not, one input to it.                                                                         |
| **Agent pick**           | The model or the effort an agent's sessions run on, picked in the agent pane's composer from the choices the agent offers. Kept per agent: every session of that agent, and every new one, runs on the latest picks from its next turn on.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | _Agent session_: the agent is per session; its picks are per agent.                                                                         |
| **Turn**                 | One message from the user to an agent session and the agent's reply to it, including the tools the agent used on the way. A turn that changed the worktree has a **turn diff**, its snapshot before → after, listed under _Turns_ in the Navigator's bar, with the agent that ran it, and shown like a commit diff. Each records its agent session.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | _Ask_: an ask starts an agent session; later messages in it are further turns. A question is one turn of the workspace's agent session.     |
| **Queued message**       | A message sent from the agent pane's composer, or a comment or review sent from the canvas, while its session's turn runs. It waits on top of the composer, with _Send now_ and ×, and runs as the next turn when the running one ends, in the order sent. _Send now_ **steers**: the message goes into the running turn, which carries on with it; a comment can't be steered, its answer must come in its own turn. A queued comment's thread says _Queued_; taken off the queue, its question becomes a note again.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | _Turn_: a queued message becomes one once it runs; one steered becomes part of the running one.                                             |
| **Permission prompt**    | An agent's request to use a tool it isn't allowed to use on its own, shown in the agent pane or in a question's thread with the agent's options (e.g. _Yes_, _Always_, _No_). The turn waits for the user's pick. Only what auto mode would block asks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | _Ask_: the user's message to an agent; a permission prompt is the agent asking the user.                                                    |
| **Background task**      | A command an agent left running in the background, such as a timer or a dev server, from its start until it ends. Shown on top of the agent pane's composer, each with Stop, together with the subagents the agent is running (_Agent_ and the subagent's task, no Stop of its own). When a command ends the agent is told and answers on its own, in a turn nobody sent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | _Summary job_: coxswain's own background work, shown in Activity.                                                                           |
| **Slash command**        | A command an agent offers in a session: its own (`/compact`), a skill or a custom prompt, sent as a message that starts with `/` and its name. Typing `/` in the agent pane's composer lists the session's, filtered by what follows.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | _Skill_: one kind of slash command; coxswain's own skills for views are read with a tool instead.                                           |

## How they relate

```
                 GitHub                              coxswain
  ─────────────────────────────────    ┃    ───────────────────────────────────────
  Pull request                         ┃    Workspace
    ├── Review comment ──┐             ┃      └── Entries: note │ question │ answer │ explanation │ finding, in threads
    └── Conversation ────┴── Comment ◀─┃─post──       │ anchored to a file diff
                                       ┃              │
                                       ┃        ask ──────────▶ Agent session (agent pane) ──▶ file diffs
                                       ┃        question ─────▶ the same session  ──▶ answer
                                       ┃                                        │ runs in
                                       ┃                                        ▼
                                       ┃                                    Worktree
```

- A **project** has one repository and any number of worktrees. A project that isn't on GitHub has
  no PRs, comments or posting, but branch workspaces, notes, questions, views and agents work the same.
- A **PR** belongs to one GitHub repository. Reviewing it uses a PR worktree on its head branch.
- **Entries** live in coxswain; **comments** live on GitHub. A note becomes a comment only when the
  user posts it. Review comments come back as mirrored entries, so GitHub's threads and the user's share one queue.
- The expected loop: review the diff, leaving comments and sending some to the agent; the agent
  answers or changes code; look at the result; at the end, post what a collaborator should see.
- **Questions** are turns of the agent pane's session, so a question on one file diff can build on
  earlier ones and on the chat (ADR 0021).
- An **agent session** runs in one worktree. For an _ask_ that changes code, where the result goes
  depends on the worktree:
  - when reviewing a PR, the agent session works in the PR worktree, so its changes land on the PR's
    branch;
  - for feature work, the agent session works in its own worktree on a new branch.
- A worktree can have several agent sessions over time. Several agent sessions at once in one
  worktree would conflict, so parallel agents mean parallel worktrees, and so parallel workspaces.

## Out of scope for now

- **Remote worktrees:** worktrees on connected remote machines. The core is built so this is
  possible later ([ADR 0002](../adr/0002-standalone-electron-app.md)); for now all worktrees are
  local.

## Open questions

1. **One PR, several workspaces?** Each workspace has its own worktree. E.g. two agents trying different fixes for the same notes.
   If so, only one of them can be the PR worktree; the others need a way to bring their result
   onto the PR branch.
